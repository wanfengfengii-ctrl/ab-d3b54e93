# 古建屋面临时防雨层 · 导排审计

现场工程师在屋面网格图上逐格标注**整数高程**、**排水口**与**不可过水的脆弱接缝**，
随后在浏览器本地发起审计：应用按共享边模拟水流，确认临时防雨层不会把雨水引入病害区域。
零运行时依赖的纯静态应用，全部计算在浏览器内完成。

## 水流与审计规则

- **允许流向**：水每一步流向「相邻（共边）且高度不高于当前格」中的**最低格**；
  并列最低时，每个并列格都是一个允许流向。排水口为终点（水进入即被收集）。
- **失效**（任一允许流向出现以下情形即整体失效）：
  - **边界外流**：边界格没有任何允许流向，雨水溢出屋面边界；
  - **无去路**：内部格四周更高，水流无处可去（洼地积水）；
  - **进入脆弱接缝**：允许流向跨越不可过水的脆弱接缝；
  - **等高区域循环**：水流在等高区域中打转，永远到不了排水口。
- **全覆盖审计**：审计覆盖每个普通格的**全部允许流向**——任何一条允许流向失效，
  整体即不安全；不能因存在一条通往排水口的路线就判定安全。
- **不安全**：按行优先返回首个问题起点，并在网格上按步序标出一条可复核的失效流向链
  （链的每一步都是允许流向，可用领域函数 `verifyFailureChain` 逐步复核）。
- **安全**：给出每格可达排水口的结论，以及每个排水口的汇水格集合（可点击高亮）。
- **结论失效**：任何草稿修改（高程、排水口、脆弱接缝、尺寸）都会使旧结论失效，
  直至重新审计。

## 快速开始（Docker）

```bash
# 启动静态 Web 服务（宿主机端口默认 8080，可用 WEB_PORT 覆盖）
docker compose up --build web
WEB_PORT=9000 docker compose up --build web
# 打开 http://localhost:8080 （或 http://localhost:9000）

# 一次性验证：代码测试 + 生产构建 + 导排领域冒烟，退出码即结果
docker compose run --rm verify
echo $?   # 0 = 全部通过，非 0 = 失败
```

`web` 服务内置健康检查（`GET /healthz`，Dockerfile `HEALTHCHECK` 与 Compose
`healthcheck` 双声明），`docker compose ps` 可查看健康状态。

## 本地开发（无需 Docker，需 Node ≥ 20）

```bash
npm start          # 开发静态服务器 http://localhost:8080（服务 src/）
npm test           # 单元测试（node:test，含界面接线冒烟）
npm run build      # 生产构建：src/ → dist/（语法检查、内容指纹、引用校验、manifest）
npm run smoke      # 导排领域冒烟（领域场景 + 构建产物检查）
npm run verify     # 一次性跑完 测试 → 构建 → 冒烟，以退出码报告
```

## 目录结构

```
src/
  flow.js       领域逻辑（纯函数，浏览器与 Node 共用）：水流、审计、失效链复核
  examples.js   内置安全/病害示例屋面
  app.js        界面交互：指针逐格编辑、审计、结论与失效链渲染
  index.html    页面
  styles.css    样式
  healthz       健康检查端点
scripts/
  build.mjs     生产构建
  smoke.mjs     导排领域冒烟
  verify.mjs    一次性验证（测试 + 构建 + 冒烟）
  serve.mjs     本地开发静态服务器
tests/          node:test 单元测试（领域 + 界面接线）
deploy/nginx.conf
Dockerfile      多阶段：verify（一次性验证）/ build（产物）/ web（nginx 静态服务）
docker-compose.yml
```

## 界面操作

1. 选择工具：**高程**（在输入框设定整数值后点击/拖动涂刷格子）、**排水口**
  （点击格子切换）、**脆弱接缝**（点击两格之间的接缝切换）。
2. 点击任意格子，状态行会显示其高程与全部允许流向，便于逐步复核。
3. 点击**发起审计**：
   - 未通过 → 显示行优先首个问题起点、失效类型，并在网格上按步序标出失效流向链；
   - 通过 → 显示每格可达排水口（逐格结论）与各排水口的汇水格集合
     （点击排水口卡片可在网格上高亮其汇水区）。
4. 修改草稿后结论立即标记为「已失效」，需重新审计。
